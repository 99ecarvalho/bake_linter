# URI002 - Git SRCREV Validity

**Severity:** warning

**Category:** source

**Enabled by Default:** Yes

---

## Description

Validates git SRCREV format and git URI consistency

## Example of Bad Code

```bitbake
# Invalid SRCREV format and inconsistent usage

SRC_URI = "git://github.com/example/project.git;branch=main"
SRCREV = "1234abcd"   # not a 40-char SHA-1, will be flagged

# Or: SRCREV set without any git:// URI
SRCREV = "9f0c3e1e2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c"
SRC_URI = "https://example.com/source.tar.gz"  # non-git source
```

## Why This Is Bad

`SRCREV` must be a valid 40-character commit hash (or `${AUTOREV}`) and only
applies to git sources. Invalid formats or setting `SRCREV` without a git URI
indicates configuration errors and can break reproducibility.

## How to Fix It

```bitbake
# Correct: pin to a valid commit hash with a git source

SRC_URI = "git://github.com/example/project.git;protocol=https;branch=main"
SRCREV = "9f0c3e1e2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c"  # 40-char SHA-1

# If using a non-git source, remove SRCREV entirely
SRC_URI = "https://example.com/project-1.0.tar.gz"
```

Validate that `SRCREV` is a 40-character SHA-1 (or a variable reference),
and that the recipe has a matching `git://` (or `gitsm://`) SRC_URI. Remove
`SRCREV` for non-git sources.
