# Rules

bake_linter has one page per rule in this directory. Each page gives the
rule's severity and default state, an example that triggers it, why it
matters, how to fix it, and how to suppress it.

When the linter reports `LICENSE001`, open [LICENSE001.md](LICENSE001.md).
The HTML report links each finding to its page.

## Severities

- **error**: the recipe is wrong, or BitBake or its QA checks will reject it.
  The run exits with code 2.
- **warning**: the recipe probably does something unintended, or relies on a
  fragile or unsafe practice. The run exits with code 1 when there is no
  error.
- **info**: a style or maintenance suggestion. It does not change the exit
  code.

Every rule's severity can be changed, and every rule can be turned off, in
`.bake-linter.yaml`; see the main [README](../../README.md#configuration).

## Index

The tables below are generated from the rule classes. After adding a rule or
changing its name, description, severity or default state, regenerate them:

python -m bake_linter.utils.gen_docs --index

## Writing a rule page

New pages start from [template.md](template.md):

```bash
python -m bake_linter.utils.gen_docs --rule MYRULE001
```

Fill in a minimal example that triggers the rule, the reason it matters for
a BitBake build, and the corrected code. Keep the examples generic: no
company, product or machine names.
