# MANDATORY001 - Summary or Description Required

**Severity:** warning

**Category:** mandatory

**Enabled by Default:** Yes

---

## Description

Every recipe should have either a SUMMARY or DESCRIPTION variable (preferably both) to explain what the recipe provides. This helps users understand the purpose of the package.

## Example of Bad Code

```bitbake
LICENSE = "MIT"
SRC_URI = "https://example.com/source.tar.gz"

# No SUMMARY or DESCRIPTION - what does this do?
```

## Why This Is Bad

Without SUMMARY or DESCRIPTION:
- **Poor user experience**: Users don't know what this package does
- **Package management**: Package managers display confusing information
- **Documentation**: Automated documentation generation fails
- **Maintenance**: Future maintainers struggle to understand the purpose
- **Best practices**: OpenEmbedded styleguide recommends descriptive metadata

## How to Fix It

Add at least a SUMMARY, preferably both SUMMARY and DESCRIPTION:

```bitbake
SUMMARY = "Example utility for data processing"
DESCRIPTION = "A command-line tool that processes data files \
in various formats and outputs results in JSON. Supports \
CSV, XML, and plain text input formats."

LICENSE = "MIT"
SRC_URI = "https://example.com/source.tar.gz"
```

### Best Practices

**SUMMARY:**
- Keep it short (one line, under 80 characters)
- Start with a capital letter, no period at the end
- Describe what the package *is*, not what it *does*
- Example: "Fast JSON parser library" not "Parses JSON files"

**DESCRIPTION:**
- Can be multiple lines (use backslash continuation)
- More detailed explanation
- Can include features, use cases, etc.
- Should add value beyond SUMMARY

### Examples

Good summaries:
```bitbake
SUMMARY = "Python HTTP library"
SUMMARY = "Tool for managing system containers"
SUMMARY = "GTK+ based image viewer"
```

Bad summaries:
```bitbake
SUMMARY = "test"  # Too vague
SUMMARY = "This recipe installs foo"  # Describes action, not content
SUMMARY = "Very very very long description that should really be in DESCRIPTION instead because it's way too detailed"  # Too long
```

## Inline Suppression

For rare cases like meta-packages or special recipes:

```bitbake
# nolint: MANDATORY001
# This is a meta-package with no direct functionality
LICENSE = "MIT"
RDEPENDS:${PN} = "other-packages"
```
