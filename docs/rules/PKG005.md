# PKG005 - RDEPENDS Package Existence

**Severity:** warning

**Category:** packaging

**Enabled by Default:** Yes

---

## Description

Ensures packages referenced in RDEPENDS:pkg are in PACKAGES

## Example of Bad Code

```bitbake
PACKAGES = "${PN} ${PN}-dbg"

RDEPENDS:${PN}-tools = "${PN}-helpers"  # ${PN}-helpers not defined in PACKAGES
```

## Why This Is Bad

BitBake silently ignores `RDEPENDS` (and the other per-package variables) of a package that is never created. The assignment is dead metadata: the dependencies it was meant to add are missing at runtime, usually because the package was renamed or a typo crept into its name.

The rule follows what BitBake would see: continuation lines, `${PN}` and `${BPN}` (expanded on both sides), values held in local variables, names inside inline expressions, `PACKAGES_DYNAMIC` patterns, required and included files, and the packages that classes add (`${PN}-src`, `${PN}-lic`, `${PN}-bin` with `lib_package`, `${PN}-ptest` with `ptest` and its variants, the `BBCLASSEXTEND` native and nativesdk variants). It stays silent where the package list cannot be known statically: a `.bbappend` or `.inc` that does not replace `PACKAGES`, `PACKAGES` set from Python, or an include that cannot be found.

## How to Fix It

```bitbake
PACKAGES = "${PN} ${PN}-dbg ${PN}-helpers ${PN}-tools"

FILES:${PN}-helpers = "${libdir}/myapp/helpers/*"
RDEPENDS:${PN}-tools = "${PN}-helpers"
```

Define every package referenced in `RDEPENDS` inside `PACKAGES`, and ensure `FILES:pkg` selects the installed paths for that package. Adjust or drop the dependency if the package is not needed.
