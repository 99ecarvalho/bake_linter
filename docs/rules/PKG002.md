# PKG002 - FILES Not Matching Installed Paths

**Severity:** warning

**Category:** packaging

**Enabled by Default:** Yes

---

## Description

Detects installed files that may not be covered by FILES

Destinations under directories the default FILES packages are not judged:
`${bindir}`, `${sbindir}`, `${libdir}`, `${libexecdir}`, `${datadir}`,
`${sysconfdir}`, `${localstatedir}`, `${includedir}`, the doc directories,
`${base_bindir}`, `${base_sbindir}`, `${base_libdir}`,
`${nonarch_base_libdir}`, `${nonarch_libdir}`, the systemd unit directories,
and `/usr`, `/etc`, `/var`, `/lib`, `/bin`, `/sbin`, `/run`. With `systemd`
inherited `${systemd_unitdir}/system` is packaged too, and with a `ptest`
class `${PTEST_PATH}`.

Any other destination must be covered by the FILES of some package
(`FILES:${PN}`, `FILES:${PN}-foo`, `FILES:mypkg-extra`), here or in a
required or included file. A file whose includes cannot be found is not
judged, nor is a `.bbappend` that only adds to the base recipe's FILES.

## Example of Bad Code

```bitbake
do_install() {
    oe_install -m 0755 ${S}/myapp ${D}${bindir}/
    oe_install -m 0644 ${S}/config.conf ${D}/etc/
    oe_install -d -m 0755 ${D}/var/lib/myapp
}

FILES = "${bindir}/* ${sysconfdir}/*"  # Missing /var/lib/myapp
```

## Why This Is Bad

If FILES patterns don't cover all installed files, some files will be lost during packaging or end up in the wrong package. This causes missing files in deployed images and runtime failures.

## How to Fix It

```bitbake
do_install() {
    oe_install -m 0755 ${S}/myapp ${D}${bindir}/
    oe_install -m 0644 ${S}/config.conf ${D}${sysconfdir}/
    oe_install -d -m 0755 ${D}${localstatedir}/lib/myapp
}

FILES = "${bindir}/* ${sysconfdir}/* ${localstatedir}/lib/${PN}/*"
```

Audit installed files against FILES patterns. Use Yocto variables (${bindir}, ${sysconfdir}, ${localstatedir}) to ensure coverage of all paths
