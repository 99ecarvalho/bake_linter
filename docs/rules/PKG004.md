# PKG004 - FILES and PACKAGES Consistency

**Severity:** warning

**Category:** packaging

**Enabled by Default:** Yes

---

## Description

Verifies FILES entries match packages defined in PACKAGES

Each `FILES:<package>` must name a package the recipe creates. The package
list is read the way BitBake builds it: `PACKAGES` and `PACKAGE_BEFORE_PN`
across continuation lines and local variables, `${PN}`/`${BPN}` and the
literal recipe name as the same package, the standard packages
(`${PN}-dev`, `-dbg`, `-doc`, `-staticdev`, `-locale`, `-src`, `-lic`), the
packages classes create (`ptest*`, `lib_package`, `bash-completion`,
`gnome-help`, `breakpad`, and the `-dbg`/`-dev`/`-ptest` flavours
`packagegroup` adds), `PACKAGES_DYNAMIC` regular expressions, and what
required or included files add. `FILES_SOLIBSDEV` and other `FILES_<NAME>`
variables are not FILES of a package.

The file is not judged when the list cannot be known from it: an include
that cannot be found, a `.inc` or `.bbappend` that does not assign the whole
`PACKAGES`, `PACKAGES` built from Python, `do_split_packages()` or
`PACKAGESPLITFUNCS`, or a package list naming a variable set elsewhere.

## Example of Bad Code

```bitbake
PACKAGES =+ "${PN}-tools"
FILES:${PN}-tools = "${bindir}/mytool"
FILES:${PN}-extras = "${datadir}/extras"  # ${PN}-extras is never created
```

## Why This Is Bad

Inconsistent `PACKAGES` and `FILES` mappings cause content to end up in unexpected packages, or to be unshippable. QA errors can result when declared packages contain no files, or files are assigned to packages that don’t exist.

## How to Fix It

```bitbake
PACKAGES =+ "${PN}-tools ${PN}-extras"
FILES:${PN}-tools = "${bindir}/mytool"
FILES:${PN}-extras = "${datadir}/extras"
```

Ensure every declared package in `PACKAGES` has a corresponding `FILES:<pkg>` entry, and that `FILES` only references packages that exist.
