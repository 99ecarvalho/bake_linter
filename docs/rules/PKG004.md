# PKG004 - FILES and PACKAGES Consistency

**Severity:** warning

**Category:** packaging

**Enabled by Default:** Yes

---

## Description

Verifies FILES entries match packages defined in PACKAGES

## Example of Bad Code

```bitbake
# PACKAGES declares a subpackage but FILES misses it
PACKAGES += "${PN}-dev"
FILES:${PN} += "${bindir}/mytool"
# Missing: FILES:${PN}-dev
```

## Why This Is Bad

Inconsistent `PACKAGES` and `FILES` mappings cause content to end up in unexpected packages, or to be unshippable. QA errors can result when declared packages contain no files, or files are assigned to packages that don’t exist.

## How to Fix It

```bitbake
# Declare packages and match FILES for each
PACKAGES += "${PN}-dev"
FILES:${PN} += "${bindir}/mytool"
FILES:${PN}-dev += "${includedir}/*"
```

Ensure every declared package in `PACKAGES` has a corresponding `FILES:<pkg>` entry, and that `FILES` only references packages that exist.
