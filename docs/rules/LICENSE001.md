# LICENSE001 - License Required

**Severity:** error

**Category:** license

**Enabled by Default:** Yes

---

## Description

Every recipe must define a LICENSE variable to clearly specify the software license terms under which the recipe's software is distributed. This is a fundamental requirement in Yocto/OpenEmbedded.

## Example of Bad Code

```bitbake
SUMMARY = "Example recipe"
DESCRIPTION = "This recipe is missing a license"
SRC_URI = "https://example.com/source.tar.gz"
```

## Why This Is Bad

Without a LICENSE variable:
- **Legal compliance issues**: You cannot legally distribute the software without knowing its license
- **Build failures**: Some workflows require LICENSE to be set
- **Unclear licensing**: Developers and users don't know the terms under which they can use the software
- **OpenEmbedded policy**: The styleguide requires LICENSE to be present

The LICENSE variable is mandatory in all recipes. A recipe may still take it from elsewhere, and the rule follows those cases: a file it requires or includes that sets LICENSE, and the classes that give it a default (`packagegroup`, `image` and `core-image` set `LICENSE ?= "MIT"`, `devicetree` sets `LICENSE ?= "GPL-2.0-only"`). When an included file cannot be found, whether it sets LICENSE is unknown and nothing is reported.

## How to Fix It

```bitbake
SUMMARY = "Example recipe"
DESCRIPTION = "Example with proper license"
LICENSE = "MIT"
SRC_URI = "https://example.com/source.tar.gz"

# For dual-licensed or multi-component packages
LICENSE = "MIT | GPL-2.0-only"

# For proprietary/closed source
LICENSE = "CLOSED"
```

**Important Notes:**
- Use SPDX license identifiers (e.g., "MIT", "GPL-2.0-only", "Apache-2.0")
- For multiple licenses, use `&` for AND relationship, `|` for OR relationship
- See the OpenEmbedded license list for valid identifiers

## Inline Suppression

If you have a very specific case where LICENSE truly should not be defined (this is rare!), you can suppress this warning:

```bitbake
# nolint: LICENSE001
SUMMARY = "Special case recipe"
```

**Warning:** Suppressing this rule is almost never the right solution. Consider if your recipe should inherit a class that provides LICENSE.

## Configuration

This rule can be configured in `.bake-linter.yaml`:

```yaml
rules:
  LICENSE001:
    enabled: true
    severity: error  # Can be: error, warning, info
```
