# URI001 - SRC_URI Protocol Consistency

**Severity:** info

**Category:** source

**Enabled by Default:** Yes

---

## Description

Detects mixed protocol usage across SRC_URI entries

## Example of Bad Code

```bitbake
SRC_URI = "https://example.com/file1.tar.gz"
SRC_URI += "git://github.com/project/repo.git;branch=main"
SRC_URI += "ftp://mirror.example.com/data.tar.bz2"
```

## Why This Is Bad

Mixing download protocols (HTTPS, git, FTP) suggests inconsistent source management. Standardizing on one protocol improves clarity and reproducibility.

## How to Fix It

```bitbake
# Use consistent protocol across all SRC_URI entries
SRC_URI = "https://example.com/file1.tar.gz"
SRC_URI += "https://example.com/file2.tar.gz"
SRC_URI += "https://mirror.example.com/data.tar.bz2"
```

Standardize on HTTPS (most secure) or a single mirroring setup. Use consistent protocols for all SRC_URI entries to clarify intent and improve maintainability.
